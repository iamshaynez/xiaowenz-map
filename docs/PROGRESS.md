## 验收阶段修掉的缺陷（留作提醒）

每一条都是先由"看图的模型说了什么"、数字检查或你用过之后的一句话发现，再用像素和着色器源码核实：

- **滚轮缩放的锚点不对**（D054，你看出来并指出的）。指针位置按 CSS 像素取却当成画面内部的像素用，桌面上偏了一倍；锚点又取在海平面高度上，山坡和楼顶会往上跑。教训：输入的坐标换算要在"一个内部像素不等于一个 CSS 像素"的页面上测，而所有测试都跑在两者相等的 960×540 页面上。

- **建筑的颜色和层高没有生效**（D048）。单通道纹理被当成向量读，`texelFetch` 返回 `(值, 0, 0, 1)`。教训：颜色表加进烘焙数据之后，从来没有用数字验证过"画面里出现了几种墙色"。现在 `landmark-views.cjs` 检查手工地标露出来的像素里有没有它自己的颜色。
- **给地标让位的建筑没有被标掉**（D041）：标记加在了一个事后另算的数组上。教训：管线里"算出了什么"和"写进了网页读的那份"要用测试连起来（`FlagClearedTest`、`CorridorTest`）。
- **取景没有算地面高度**，页面用的是没有模型的地标表（D041）。
- **雪落在水面上**：破边的噪声可以给覆盖率为 0 的类别加出雪来（D041）。
- **桥面比路面低两米**：桥也被"埋进地面两米"（D041）。
- **贴地的东西按 DEM 取高，网格却按另一种方式画**：水面会沉到网格下面（D044）。
- **转一下相机地标就出画面**（D049）。
- **往帧缓冲里画的着色器必须两个颜色输出都写**：只写一个，Chrome 报 INVALID_OPERATION、什么都不画，而且不报在控制台里。调试用的着色器第一次就栽在这里。
- **钱塘江大桥的模型定义了没有接上**（D052）。教训：文档里说"有几个手工模型"之前，要对着烘焙出来的地标表数一遍。
- **视觉模型的话要逐条用数字核实**（D047）：这一轮它说对的是地标被压住、雪落在水上；说错的是"转台的六张图可能是重复的"（实测两两 94–97% 的像素不同）、"东站屋顶没有肋"。
