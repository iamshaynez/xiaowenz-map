- **验收阶段抓到一个从阶段 4 起就存在的错**（D048）：建筑的着色器把属性纹理读错了，全城的墙一直是同一种灰白、屋顶一直是同一种浅灰，一层楼按一米画。修好之后颜色表第一次真正生效，所以**交付版的外观是第一次成型的外观**。
- **画面不是逐像素一样了**（D058）。数据里的位置从浮点改成 4 厘米一格的整数之后，着色器的颗粒噪声重排：54 张对照帧和改之前比，2.96% 的像素不同，其中 1.48 个百分点是同一种颜色差一级明暗，肉眼分不出，逐像素比会看到。这是压缩本身的代价，做不到既省这七成空间又逐像素不变。其余的差异来自下一条。
- **楼的总数以前多报了 18%**（D059）。3D-GloBFP 给三分之一的轮廓记了两条高度不同的记录，以前两条都画，重合的墙转动时会闪；数据报告里还把它们解释成了"同一栋楼的不同部分"，是错的。现在每个轮廓只留较高的一条：入图的楼 538,635 → 439,889，天际线不变，这些楼的下半截墙换了颜色。
- **交付版的验收图只复核了一部分**。我自己看不了图，靠"读图—转给视觉模型"的工具。修正颜色之后复核了 8 张地标图（断桥、保俶塔、雷峰塔、净慈寺、城隍阁、灵隐寺、六和塔、拱宸桥）：每张都确认地标在画面里、看得出是什么、标签可读。其余 16 张地标图和四季、缩放、转台、俯视四张，复核到一半时这个工具不再能调用，之后没有补上；它们只过了数字检查（`tour.cjs`、`landmark-views.cjs`）。工具恢复后要做的：把 `docs/REVIEW/` 里剩下的图逐张过一遍视觉模型，做法见 D040、D047。

## 验收阶段修掉的缺陷（留作提醒）

每一条都是先由"看图的模型说了什么"、数字检查或你用过之后的一句话发现，再用像素和着色器源码核实：

- **楼高数据集的重复记录画了两遍**（D059），而且数据报告把它们说成了"同一栋楼的不同部分"。教训：`shapely.equals` 对相差亚毫米的两个多边形判为不等，"几何完全相等"不等于"是同一个东西"；对外接框相同的记录应该比面积、中心和豪斯多夫距离。这些墙的下半截以前每个像素显示哪一条由深度缓冲的舍入决定，转动时会闪——这种"随视角变的随机"只有转着看、或者逐像素比对两个版本才看得出来。
- **回到全景的缩放按当前缩放算**（D057）。教训：导览测试里"回到全景"只查了"缩放小于某个值"，没查它等于该有的那个值，所以从近处按 R 回不到全景一直没被发现。
- **滚轮缩放的锚点不对**（D054，你看出来并指出的）。指针位置按 CSS 像素取却当成画面内部的像素用，桌面上偏了一倍；锚点又取在海平面高度上，山坡和楼顶会往上跑。教训：输入的坐标换算要在"一个内部像素不等于一个 CSS 像素"的页面上测，而所有测试都跑在两者相等的 960×540 页面上。

- **建筑的颜色和层高没有生效**（D048）。单通道纹理被当成向量读，`texelFetch` 返回 `(值, 0, 0, 1)`。教训：颜色表加进烘焙数据之后，从来没有用数字验证过"画面里出现了几种墙色"。现在 `landmark-views.cjs` 检查手工地标露出来的像素里有没有它自己的颜色。
- **给地标让位的建筑没有被标掉**（D041）：标记加在了一个事后另算的数组上。教训：管线里"算出了什么"和"写进了网页读的那份"要用测试连起来（`FlagClearedTest`、`CorridorTest`）。
- **取景没有算地面高度**，页面用的是没有模型的地标表（D041）。
- **雪落在水面上**：破边的噪声可以给覆盖率为 0 的类别加出雪来（D041）。
- **桥面比路面低两米**：桥也被"埋进地面两米"（D041）。
- **贴地的东西按 DEM 取高，网格却按另一种方式画**：水面会沉到网格下面（D044）。
- **转一下相机地标就出画面**（D049）。
- **往帧缓冲里画的着色器必须两个颜色输出都写**：只写一个，Chrome 报 INVALID_OPERATION、什么都不画，而且不报在控制台里。调试用的着色器第一次就栽在这里。
- **钱塘江大桥的模型定义了没有接上**（D052）。教训：文档里说"有几个手工模型"之前，要对着烘焙出来的地标表数一遍。
- **视觉模型的话要逐条用数字核实**（D047）：这一轮它说对的是地标被压住、雪落在水上；说错的是"转台的六张图可能是重复的"（实测两两 94–97% 的像素不同）、"东站屋顶没有肋"。

阶段 3 以前的缺陷清单见 git 历史里这份文件的上一版。
